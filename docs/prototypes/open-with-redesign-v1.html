打开方式 · 补全设计示例 v1

基于当前 mossx「设置 → 打开方式」实现缺陷，对照 JetBrains External Tools、Unity External Tools、 macOS Open With / Raycast、VS Code Open in External App 的成熟模式，给出可落地的 UX 补全方案。 本页为交互原型，未改产品代码；确认方向后再进入 OpenSpec / 实现。

缺陷：白文本框 缺陷：Finder 文案 Win 不适配 缺陷：仅 macOS open 心智 参考：IDEA / Unity / Raycast 交付：先设计后实现

1. 现状问题诊断（对照你截图）

不是“少几个字段”，而是配置心智模型跨平台分裂 + 小白无法完成闭环。

当前 UI 路径
添加应用→ 手填标签→ 手填应用名 / 命令→ 祈祷可用
  • 类型文案硬编码「访达 / Finder」：数据模型 kind: "finder"，Win 上仍叫访达，心智断裂。
  • 应用 = 纯文本：用户必须知道 mac 上是 Sublime Text 还是 Sublime Text.app；Win 上应是 Code.exe 路径或 code CLI。
  • 帮助文案只讲 macOS open：底部说明写死 “应用使用 macOS open 加可选参数”。
  • 无探测 / 无试运行 / 无 Browse：小白无法从「我想用 Cursor」连到「可执行目标」。
  • 默认预设列表偏 mac 生态：Ghostty 等在 Win 无意义；缺 Explorer、Notepad、Windows Terminal 等。
代码事实源（现状）
  • UI：OpenAppsSection.tsx — Dialog 只有文本框 + 类型三段。
  • 启动：mac 走 open -a <appName>；非 mac 走 PATH / 已知安装路径猜测。
  • 文件管理器：后端已分平台（Finder / Explorer），但前端类型/文案未抽象。
  • 图标：get_open_app_icon 仅 macOS 有实现，Win 返回 null。
核心矛盾
产品把三种异构能力（系统文件管理器 / 桌面 App Bundle / 任意 CLI）压进同一套「应用名称」文本模型， 且把 mac 专用术语暴露给全平台用户。

5. 建议数据模型（设计层，非最终 schema）

兼容旧配置：kind: "finder" 读入时迁移为 fileManager。

{
OpenTarget {
  id: string
  label: string
  kind: "app" | "command" | "fileManager"   // 废弃对外 "finder"
  // app
  appRef?: {
    displayName: string          // "Visual Studio Code"
    bundleId?: string            // mac: com.microsoft.VSCode
    executablePath?: string      // win/linux 绝对路径；mac 可选 .app
    openName?: string            // mac open -a 名
  }
  // command
  command?: string
  args: string[]                 // 可含 $PATH$ $DIR$ $NAME$ $LINE$
  // runtime
  health?: "ok" | "missing" | "broken" | "unknown"
  isDefault?: boolean
}
跨平台解析优先级（app）： executablePath 存在且可读 → 直接 spawn； 否则 mac 用 openName/displayName 走 open -a； Win 用 displayName 别名表候选（现有 open_app_command_candidates）+ 常见安装路径。

6. 建议分期（确认设计后）

先止血文案与 Browse，再做探测与健康态，最后做宏与试运行。

阶段范围验收
P0 止血 fileManager 平台文案；帮助文案去 mac 专属；应用字段旁 Browse…（系统选 .app / .exe） Win 用户不再看到「访达 / macOS open」；能通过文件对话框选出 Code.exe
P1 小白路径 添加向导：本机预设网格 + 探测；未检测到时一键转 Browse 新用户 3 次点击内添加 VS Code / Cursor 且可打开工作区
P2 可靠性 健康状态徽标；失效提示；试运行；Win 图标（可选） 路径被挪走后列表显示「失效」而非静默失败
P3 高级 参数宏芯片；命令预览；工作目录（可选） 对齐 IDEA 的自定义工具场景（打开到行号等）
