1. 外观约定（已按你的要求）

  • 折叠：整条高度固定一行（约 44px）。文案超长用省略号，悬停可看全文。
  • 详情：行内 ? icon，点击弹窗，不在条上堆长文。
  • 主按钮：折叠时只露「自动处理」「跳过本轮，继续聊」+ 展开箭头。
  • 展开：多出一行高级按钮（再查一次 / 停止请求 / 换连接），默认收起。

2. 折叠时两个主按钮 · 怎么实现（大白话）

① 自动处理（主路径，优先点）

用户只点一次。前端按固定梯子自动串行跑，不把「检查 / 停止 / 重建」甩给人选：

  1. 查 owner：这轮卡在「有未决 attempt」还是「只有 binding 坏了」还是「其实已经干净」。
  2. 若已干净 → 直接解锁，结束。
  3. 若有 attempt → 调现有 recover_attempt（能接回就接回跑着的任务；能落盘就落盘）。
  4. 若仍被 Runtime 占着 → 调 interrupt_turn 停止请求（有能力才停；没有就跳过这步）。
  5. 若 binding 仍 recovery / 仍解不开 → 调 rebuild_binding（先 stop 再重建，对应现在的「停止并重建」）。
  6. 全程成功 → 经 settling 解锁；仍失败 → 条上改文案「自动没搞定」，主按钮变成「再试自动」+ 继续强调「跳过本轮」。

不做的事：不自动「跳过本轮」（那是破坏性明确选择）；不盲建第二个会话；不在 ambiguous 多 owner 时硬拆。

按钮态：处理中禁用两个主按钮 + 文案变成「处理中…」；结束后按结果解锁或保持卡住。

② 跳过本轮，继续聊（保底出口）

对应现在的「放弃本轮」，换成人话：

  1. 点一下 → 确认弹窗：「只取消未确认的上一句，对话还在，会话会解锁」。
  2. 确认后 → 调 abandon_unresolved_attempt（forceStop=true，尽量先 interrupt 再 durable cancel）。
  3. 成功 → 本轮记取消 + 解锁 Composer；重启也不该再锁同一 attempt。
  4. 失败（比如多 owner 说不清）→ toast 说明，保持锁定，可引导展开看高级选项或重开应用（这是缺陷面，要单独收）。

和自动处理的分工：自动 = 尽量保住/接上；跳过 = 我不要这轮了，先让我聊。

3. 展开后三个按钮 · 给谁用、干什么

按钮 对应现能力 干什么 何时可点 点完怎样
再查一次 检查状态 / Probe±Recover 只查、尽量接回或落盘，不自动换连接 卡住时几乎总可点 能定论就解锁/接回；不定论仍锁，更新一行摘要
停止请求 停止投递 / interrupt 掐掉 Runtime 还占着的那次投递 仅当有可 interrupt 的 in-flight attempt 仍卡住（只放 ownership），文案提示「已请求停止，可再自动处理或跳过」
换连接 停止并重建 / rebuild 归档坏掉的底层 binding，新开一条 Native 管 binding 坏 / 自动多次失败后 成功则解锁；Runtime 仍占着时先内部 stop 再 rebuild

默认用户不用展开。展开是给「自动处理失败、又不想跳过」的人，或支持远程指导时用。
